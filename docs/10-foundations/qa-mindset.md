# QA-Denkweise


Qualitätssicherung verbessert das System, das Software erstellt; Beim Testen wird ein Produkt oder eine Idee bewertet, um mehr über qualitätsbezogene Risiken zu erfahren. Sie überschneiden sich, sind aber keine Synonyme.

Nützliche Gewohnheiten:

- Fragen Sie, welches Ergebnis zählt und wem ein Misserfolg schaden könnte.
- Verwandeln Sie Annahmen in Beispiele, die diskutiert oder überprüft werden können.
- Suchen Sie nach schnellem Feedback auf dem günstigsten, nützlichen Niveau.
- Beobachten Sie das Produkt, das Liefersystem und die Betriebsumgebung.
- Machen Sie Unsicherheit sichtbar, anstatt eine falsche Pass/Fail-Antwort zu erzwingen.
- Studie entging Mängeln, ohne Einzelpersonen dafür verantwortlich zu machen.

### Fragen, die Sie frühzeitig stellen sollten

1. Welches Problem soll mit dieser Änderung gelöst werden?
2. Was darf niemals passieren?
3. Welche Benutzer, Daten, Integrationen und Umgebungen sind betroffen?
4. Wie werden wir Erfolg und Misserfolg beobachten?
5. Kann die Änderung sicher freigegeben, eingeschränkt und rückgängig gemacht werden?
