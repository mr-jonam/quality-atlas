# QA Engineer Roadmap / Roadmap QA Engineer

This learning map synthesizes common public QA curricula, including the [roadmap.sh QA Engineer roadmap](https://roadmap.sh/qa). It is an independent, vendor-neutral interpretation: tools are examples, while transferable concepts and practice are the goal.

Questa mappa sintetizza percorsi QA pubblici diffusi, inclusa la [roadmap QA Engineer di roadmap.sh](https://roadmap.sh/qa). È un'interpretazione indipendente e vendor-neutral: gli strumenti sono esempi, mentre concetti trasferibili e pratica sono l'obiettivo.

## English

### 1. Build the foundations

- Understand quality assurance, testing objectives, risk and the limits of testing.
- Compare black-box, white-box and experience-based approaches.
- Learn test oracles: requirements, models, standards, comparable products, historical behavior and expert judgment.
- Prioritize by impact, likelihood, change, usage and observability.

Read: [[../10-foundations/qa-mindset]], [[../10-foundations/testing-fundamentals]], [[../10-foundations/test-design-techniques]].

### 2. Work within delivery systems

- Recognize sequential, iterative, incremental and continuous delivery models.
- Understand verification, validation and where feedback can be introduced.
- Practice planning, exploratory testing, scenario design and defect communication.

Read: [[../10-foundations/sdlc-testing-models]], [[../40-playbooks/exploratory-session]], [[../10-foundations/defect-communication]].

### 3. Cover product risks

- Test APIs, contracts, web and mobile behavior.
- Include accessibility, security, performance, reliability and compatibility.
- Manage test data and evidence without exposing sensitive information.

Read: [[../20-intermediate/api-testing]], [[../20-intermediate/web-mobile-testing]], [[../20-intermediate/non-functional-quality]], [[../20-intermediate/test-operations]].

### 4. Engineer sustainable feedback

- Learn enough programming, browser and protocol fundamentals to diagnose failures.
- Place automated checks at the cheapest trustworthy layer.
- Use version control, reviews, CI/CD and actionable reporting.
- Treat flaky tests, logs and monitoring as engineering concerns.

Read: [[../20-intermediate/automation-engineering]], [[../20-intermediate/ci-cd-quality-gates]], [[../30-advanced/metrics-observability]].

### 5. Lead quality as a system

- Improve testability and architectural feedback loops.
- Define risk-based strategies and release evidence.
- Facilitate learning across product, engineering and operations.

Read: [[../30-advanced/testability-architecture]], [[../20-intermediate/risk-based-strategy]], [[../30-advanced/quality-leadership]].

## Italiano

### 1. Costruisci le fondamenta

- Comprendi quality assurance, obiettivi del testing, rischio e limiti dei test.
- Confronta approcci black-box, white-box e basati sull'esperienza.
- Impara gli oracoli di test: requisiti, modelli, standard, prodotti comparabili, comportamento storico e giudizio esperto.
- Definisci priorità usando impatto, probabilità, cambiamento, utilizzo e osservabilità.

### 2. Lavora nei sistemi di delivery

- Riconosci modelli sequenziali, iterativi, incrementali e continuous delivery.
- Comprendi verifica, validazione e dove introdurre feedback.
- Esercitati con pianificazione, esplorazione, scenari e comunicazione dei difetti.

### 3. Copri i rischi di prodotto

- Verifica API, contratti, comportamenti web e mobile.
- Includi accessibilità, sicurezza, performance, affidabilità e compatibilità.
- Gestisci dati di test ed evidenze senza esporre informazioni sensibili.

### 4. Progetta feedback sostenibile

- Acquisisci basi di programmazione, browser e protocolli per diagnosticare i problemi.
- Posiziona i controlli automatici al livello più economico e affidabile.
- Usa version control, review, CI/CD e report azionabili.
- Tratta test flaky, log e monitoring come problemi ingegneristici.

### 5. Guida la qualità come sistema

- Migliora testabilità e feedback architetturali.
- Definisci strategie basate sul rischio ed evidenze di rilascio.
- Facilita l'apprendimento tra prodotto, sviluppo e operations.

Use this as a compass, not a checklist. Demonstrated practice matters more than collecting tool names.

Usa questa mappa come bussola, non come checklist. La pratica dimostrabile conta più dell'accumulo di nomi di strumenti.
